# 架构与数据边界

Folio 直接使用用户项目中的 Markdown 文件。应用状态、草稿、历史和可选服务配置与原文分开保存；开发时可用 `FOLIO_DATA_DIR` 指向隔离目录。

## 代码入口

| 层 | 入口与职责 |
| --- | --- |
| 界面 | `src/App.tsx` 管理文档会话，`RichEditor.tsx` 与 `markdown.ts` 处理编辑和渲染，`AgentPanel.tsx` 展示对话与修改审阅 |
| 桌面边界 | `electron/main.cjs` 建立窗口和 IPC，`preload.cjs` 暴露有限接口；Agent、预览、项目和退出收尾按模块注册 |
| 文档与协作 | `core/file-store.cjs` 校验路径与文件版本，`encoding.cjs` 保留编码，`merge.mjs` 合并改动，`history-store.cjs` 保存历史 |
| 文档查找 | 文档目录、工作区浏览与索引 worker 将扫描工作移出前台；项目发现使用本机记录缓存 |
| 文档 Agent | `agent-service.cjs` 编排请求和修正，`agent-edit.mjs` 校验修改，`agent-documents.cjs` 限制资料读取，`agent-timeouts.cjs` 管理等待预算 |
| 模型连接 | `codex-client.cjs` 使用独立 Codex app-server；`compatible-client.cjs` 使用所配置的 Chat Completions 服务 |
| 可选集成 | `project-sync.cjs` 处理项目 iCloud 同步，`dingtalk-sync.cjs` 发布在线文档，`memos-cloud.cjs` 提供项目记忆 |
| 独立 CLI | `cli/main.cjs` 提供版本检查的文档操作，`integrations/` 分发 skill 与 plugin |
| 分发 | `scripts/publish-release.mjs` 发布明确提交的完整安装包；`core/update-*` 与原生 helper 校验和替换应用 |

发布目标来自 `package.json` 的 `repository.url`，由 `core/repository.cjs` 校验；发布脚本和应用更新共用该配置。运行时不接受界面或环境变量替换更新主机。

## 数据何时离开本机

| 功能 | 触发方式 | 数据范围 |
| --- | --- | --- |
| 本地阅读、编辑与搜索 | 打开文档或搜索 | 本机文件与本地应用状态 |
| Agent 对话 | 连接服务后主动发送 | 当前草稿或选区、明确添加的参考文档，以及按需读取的同项目资料 |
| 文档建议 | 打开已连接的 Agent 面板且对话为空 | 当前文档或选区；内容版本、语言和模型分别缓存 |
| Agent 查看渲染 | 模型调用只读预览工具 | 当前可见文档区域；不含工具栏、侧栏或对话，不持久保存预览图片 |
| MemOS | 配置当前项目并由 CLI／skill 执行记忆操作 | 指定文档线索；本地 Markdown 保持原文来源 |
| 钉钉发布 | 预览并确认发布／更新 | 当前文档转换结果和引用资源；云端已有改动时检查版本 |
| iCloud | 用户按项目开启同步 | Markdown 与引用的本地附件，单文件小于 100 MB |
| 检查更新 | 打开更新入口并检查 | GitHub 版本和资产请求；私有测试版复用本机 GitHub CLI 登录 |

API 接入凭据由系统安全存储加密。ChatGPT 接入使用 Folio 独立的 Codex 配置目录。对话与应用状态默认在 macOS 的 `~/Library/Application Support/Folio`；它们不属于源码仓库。

标签恢复偏好和标签路径保存在本机界面状态中。普通退出按用户偏好保留或清空标签记录，恢复草稿单独保存；更新重启使用一次性的恢复标记。Agent 设置记录进入位置，完成后返回原文档或设置分类，不自动发送未提交的指令。

文件操作通过短 SQLite 事务分配跨进程锁所有权；等待不阻塞主线程，退出会停止接收新操作并等待已经接收的文件任务。旧目录锁仍用于与已有 CLI 协调。来源状态保存文档身份和版本元数据，差异读取受历史预算管理的快照，不在项目身份 JSON 中复制全文。

本地图片请求绑定来源文档的项目。富文本复制只读取该项目内限定大小的图片，最多等待五秒；新的复制操作会取消上一次准备。

## Agent 工具边界

自动查找与读取限于已打开项目中的 Markdown／文本，排除隐藏、依赖、备份、归档与项目外路径。选区请求不会自动扩大为全项目读取。读取额度、预览额度和上下文上限见 [Agent 文档助手](Agent文档助手.md)。

模型提出的修改必须在当前范围内唯一定位。无效格式、缺少原文、重叠或版本变化先反馈给模型，允许有限次数修正。有效建议仍需用户查看并接受；文件写入检查版本，接受前保存历史。工具不提供终端、通用代码执行或直接写文件能力。

## 验证

`npm run check` 包含格式、核心测试、类型检查、生产构建、独立 CLI 和真实 Electron 场景。测试使用生成资料与模拟服务，不连接真实云账号。`npm run pack` 额外验证归档内 worker、CLI 与更新 helper。

真实 API 测试、分发签名和公证需要独立配置；常规检查通过不代表这些外部步骤已经完成。

## 本地诊断

`core/diagnostics.cjs` 收集启动、连接、登录、请求结果与 IPC 失败的有限元信息。严格白名单排除正文、对话、文件路径、API 地址、凭据和登录链接；导出时再次过滤。每个日志文件最多 512 KiB，保留当前与上一个文件，重复失败限频，待写队列最多 64 项。

“设置 → 关于与更新”与 Agent 设置可导出本地诊断。记录和导出均不触发网络上传。
