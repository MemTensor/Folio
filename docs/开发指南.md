# Folio 开发指南

## 环境

- macOS Apple Silicon，用于运行与打包桌面应用。
- Node.js 22.13 或更高版本、npm。
- Pandoc，仅在需要 Word 导出时安装。

```bash
npm ci
node node_modules/electron/install.js
npm run desktop
```

`npm run desktop` 启动 Vite 与 Electron。`npm run dev` 只启动浏览器演示；本机文件监听、恢复草稿和原生导出需要桌面应用。

## 常用命令

```bash
npm test         # 核心行为测试
npm run format   # 统一代码格式
npm run check    # 格式、测试、TypeScript、生产构建、隔离 CLI 与桌面启动验证
npm run pack     # 构建桌面应用
npm run dist     # 构建 ZIP 分发包
```

构建目录由 `package.json` 的 `build.directories.output` 决定，通过 `release/v${version}` 随版本号展开；发布脚本与打包使用同一解析规则。其中 `mac-arm64/Folio.app` 可直接运行，应用随包提供 CLI 运行时。发布流程见下文。

生产构建同时生成 `dist/`、`dist-cli/` 和 `third-party-licenses/`。前端依赖被编入 `dist/`，无需在应用归档中重复保存完整开发依赖；授权文本通过 `scripts/collect-licenses.mjs` 收集，清单记录在 `third-party-licenses/index.json`。

```bash
./bin/folio --help
./bin/folio doctor --json
```

## 项目结构

| 路径 | 职责 |
| --- | --- |
| `src/` | 编辑器、阅读视图和文档管理界面 |
| `electron/` | 桌面窗口、文件操作与安全通信边界 |
| `core/` | 文件版本、草稿、文档索引与可选记忆 |
| `cli/`、`bin/` | Agent 与脚本使用的命令行接口 |
| `integrations/` | Codex 和 Claude Code 接入说明与插件 |
| `examples/` | Markdown、公式和图表样例 |
| `tests/` | 文件协作、检索、格式和云接口测试 |
| `third-party-licenses/` | 构建生成的依赖授权文本与版本清单 |

代码之间的调用关系与云端数据范围见 [架构与数据边界](架构与数据边界.md)。

## 本机数据与测试

使用 `FOLIO_DATA_DIR` 将开发或测试状态与日常应用数据分开：

```bash
FOLIO_DATA_DIR=/tmp/folio-dev npm run desktop
```

源码目录不应包含 API Key、真实文档索引、恢复草稿或签名证书。本机 `.claude/` 启动配置也不纳入版本管理；可分发的插件位于 `integrations/`。常规测试使用本地生成的样例和模拟云接口，不需要 MemOS 凭据。`tests/cloud-live.cjs` 是手动真实云测试，只在明确允许时运行，凭据通过隐藏输入读取。

大规模索引测量可使用：

```bash
node scripts/benchmark-library.mjs 10000 /tmp/folio-index-benchmark.json
```

此脚本生成临时文档，记录首次索引、查询和单文件更新耗时，结束后清理样例。

构建后的 `scripts/verify-cli.mjs` 会在临时目录禁用网络，验证独立 CLI 的命令输出与公式动态字体加载。`scripts/verify-desktop.mjs` 使用真实 Electron、生产预加载接口和生成的临时文档，检查正文、工具栏与启动确认，不读取日常文档或调用云端接口。这两个脚本运行的都是源码树，不覆盖主进程的 IPC 路径校验与打包产物。

`npm run pack` 和 `npm run dist` 在打包后自动运行 `scripts/verify-package.mjs`。它从 `app.asar` 内部加载工作区浏览、文档目录的 worker，并执行随包分发的 CLI，并实际运行 SQLite 全文索引与查询，因此也确认 `runAsNode` fuse 在翻转后仍然可用。单独运行用 `npm run verify:package`。

## 开发约定

1. 围绕具体使用场景提交改动，并说明如何复现和验证。
2. 保持标准 Markdown；保留公式、表格结构、图片相对路径与文本编码。
3. 写入操作检查读取时的版本，有冲突时重新读取和审阅。
4. 基础阅读、编辑和搜索保持本地可用，可选云服务失败不应阻断文档工作。
5. 运行与改动相关的测试；涉及跨项目和保存逻辑时同时验证实际文件结果。

## 准备与发布

自动检查模板位于 `docs/ci.yml.example`，使用 macOS、Node.js 22 和只读仓库权限，执行 `npm run check` 与 `npm run pack`。需要具有 GitHub workflow 写权限的维护者将模板放入 `.github/workflows/ci.yml` 才会启用；当前仓库没有活动工作流。

发布准备脚本面向 `package.json` 中的 `repository.url`，当前为 `MemTensor/Folio` 公开仓库和 macOS arm64 ZIP。版本从 `package.json` 读取，发布说明取自 `CHANGELOG.md` 对应版本。

先完成检查、提交并推送源码，再基于确定的提交重新构建 ZIP：

```bash
npm run check
npm run dist
node scripts/publish-release.mjs
```

默认模式和 `--dry-run` 都只准备本地文件，不访问或修改 GitHub。脚本检查 ZIP 完整性、包内版本、应用标识和架构，再在构建目录生成：

- `SHA256SUMS.txt`：该版本 ZIP 的 SHA-256。
- `RELEASE_NOTES.md`：面向使用者的功能说明及安装信息。
- `release-plan.json`：版本、明确提交和资产校验信息。

包内 `updater/build-info.json` 记录构建提交和工作区状态；发布脚本拒绝旧提交或未提交源码构建的安装包。可以在默认分支同一提交的干净 detached worktree 中构建和发布。

准备过程将当前 HEAD 记录在计划中，但版本校验不能证明 ZIP 的每个字节都来自该提交。发布者应在源码提交确定后重新构建，避免复用同版本号的旧安装包。

确认本次公开发布后执行：

```bash
node scripts/publish-release.mjs --publish --commit FULL_HEAD_SHA --visibility public
```

`FULL_HEAD_SHA` 是当前 HEAD 的完整 40 位小写 SHA。脚本要求工作区干净、当前分支的远端 HEAD 与它一致、仓库可见性与 `--visibility` 选择一致。未指定时仅允许私有仓库；公开发布必须明确传入 `--visibility public`。脚本不会推送源码或改变仓库可见性。若远端 tag 尚不存在，仅在 `--publish` 模式下按这个明确 SHA 创建；已有 tag 指向不同提交时立即停止。

实际发布顺序是创建草稿、上传缺失资产、从 API 回读文件大小和摘要、最后发布。同版本草稿可以继续执行；匹配资产会复用，不覆盖。已经发布且资产完全匹配时返回 `already-published`；发现任何差异则停止，不能通过覆写旧包修正已发布版本，应使用新的版本号。

脚本通过 `gh` 使用本机登录，发布账号需要仓库写权限。网络或上传中断后，先检查保留的草稿，再重复执行同一命令。脚本不会自动删除已有资产、移动 tag 或把失败发布当作成功。

应用更新端只接受完整的版本 ZIP 和校验文件。发布准备脚本以规范的 `major.minor.patch[-prerelease]` 命名版本，不接受构建元数据后缀。Beta 版本作为 GitHub prerelease 发布，正式版本作为正式 Release 发布。

## 分发状态

桌面包目前采用本地构建配置，尚未配置 Developer ID 签名与 Apple 公证。源码采用 Apache-2.0，并随附 NOTICE；发布时仍需保留第三方授权声明并核对分发产物。

打包时通过 `build.electronFuses` 关闭 `NODE_OPTIONS` 与 `--inspect` 参数，并要求只从 `app.asar` 加载应用代码。`runAsNode` 保持开启：`Contents/Resources/bin/folio` 依赖 `ELECTRON_RUN_AS_NODE` 运行内置 CLI。这意味着本机上任何以当前用户身份运行的进程仍可把 Folio 当作 Node 解释器启动，从而继承它已获得的文件访问授权；在为内置 CLI 换成独立运行时之前，这一点无法关闭。`app.asar` 完整性校验同样留待 Developer ID 签名落地后再开启，否则能改写 bundle 的人也能重新生成 ad-hoc 签名。

详见 [开源与分发说明](开源与分发说明.md)。

编辑器回归可单独运行 `node scripts/verify-editor-regressions.mjs`，使用生成内容验证光标移动缓存、任务块复用、图片复制与选区映射；已纳入 `npm run check`。
