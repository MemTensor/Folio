# 钉钉集成说明

将本地 Markdown 发布为同事可阅读、编辑的钉钉在线文档。此功能目前为实验性；版本变化见 [更新记录](../CHANGELOG.md)。

## 准备

安装官方 [DingTalk Workspace CLI](https://github.com/DingTalk-Real-AI/dingtalk-workspace-cli)，并在本机登录：

```bash
dws auth login --recommend
dws profile list --format json
```

接口适配基于 dws v1.0.62。Folio 复用本机登录态，钉钉凭据保留在本机。

## 从 Folio 发布

1. 保存当前文档，处理待审阅的本地修改。
2. 点击“发布或同步到钉钉”。
3. 检查账号、文件和内容摘要，点击“发布到钉钉”。首次创建到所选账号的“我的文档”。
4. 创建后可打开钉钉文档、复制链接，或展开“发送链接给同事”。消息发送需要单独填写接收人并确认；访问权限仍在钉钉中管理。

再次发布会更新已关联的同一篇在线文档。预览绑定本地版本，更新使用钉钉服务端版本检查。文件或图片在预览后变化时，需要重新生成预览；云端出现独立修改时暂停同步。目前不提供双向自动合并。

## 发布未完成时

先点击“检查上次结果”。即使创建已成功而回读失败，Folio 也会保留已知文档 ID，优先核对现有文档。

“同步问题处理”提供以下方式：

| 情况 | 操作 |
| --- | --- |
| 创建回执未返回 ID，但在钉钉找到了文档 | 填写文档 ID，读取云端版本；内容与上次提交一致后确认关联 |
| 已核实没有创建文档 | 确认未创建，结束待确认状态；下一次发布仍需单独确认 |
| 同事修改了已关联文档 | 读取云端内容并查看差异，保留需要的内容后再决定更新方式 |
| 以后希望单独管理这篇云端文档 | 解除关联，钉钉现有文档继续保留；下一次发布会创建新文档 |

“采用云端当前版本作为同步起点”只记录当前远端版本，并保留云端内容。**下一次确认更新仍会用本地内容替换它**，发布预览会展示两个版本的文字节选。需要保留同事修改时，先将它们合入本地原文。公式、图表和完整排版请在钉钉中核对。

链接发送结果不明确时，先逐一核对接收人，再确认“全部送达”或“均未送达”。部分送达时，可先在钉钉手动补发缺失接收人，再确认全部送达。记录核对结果不会自动发送消息。

## Agent CLI

以下命令在 Folio 源码目录运行；安装版可将 `./bin/folio` 换成 `/Applications/Folio.app/Contents/Resources/bin/folio`。

```bash
./bin/folio dingtalk status notes.md --workspace /path/to/project --json
./bin/folio dingtalk plan notes.md --workspace /path/to/project --json
./bin/folio dingtalk sync --plan PLAN_ID --workspace /path/to/project --yes --json
./bin/folio dingtalk check notes.md --workspace /path/to/project --json
```

`--yes` 表示这次计划已经得到确认，不能因为生成了预览就推定允许上传。计划有效期为 10 分钟；过期或内容变化后重新生成。

### Mermaid 图片

桌面入口会生成并关联图片。CLI 可通过 `--diagram-file` 提供 JSON 数组，顺序与源码中的 Mermaid 围栏一致，每项包含原始源码与 PNG：

```json
[{"source":"graph TD\nA-->B\n","png":"data:image/png;base64,PNG_BASE64"}]
```

`source` 是围栏内部的完整文本，包含原有末尾换行。带属性的 `mermaid` 围栏同样计入。携带图表时必须同时提供生成图片时读取的文档 hash：

```bash
./bin/folio dingtalk plan notes.md --workspace /path/to/project \
  --diagram-file diagrams.json --expect DOCUMENT_HASH --json
```

Folio 检查文档版本、源码和图表数量；仅由来源名称或数组下标推断的图片不能直接提交。

### 恢复关联

先读取当前绑定或候选文档；`--node-id` 仅用于尚未取得 ID 的待确认创建：

```bash
./bin/folio dingtalk recovery notes.md --workspace /path/to/project --json
./bin/folio dingtalk recovery notes.md --workspace /path/to/project --node-id NODE_ID --json
```

从返回结果取 `binding.planId` 和 `remote.revision`，核对后执行：

```bash
./bin/folio dingtalk recover notes.md --workspace /path/to/project \
  --action attach --node-id NODE_ID --expected-plan-id BINDING_PLAN_ID \
  --remote-revision REMOTE_REVISION --yes --json
```

`--action` 还支持 `adopt-remote`、`detach` 和 `confirm-not-created`。采用远端基线需要刚刚核对的 `--remote-revision`；解除关联与确认未创建均需要当前 `--expected-plan-id`。恢复操作保留本地记录，并使旧发布计划失效。

消息发送核对命令为 `dingtalk share-status` 与 `dingtalk share-resolve`；参数及授权边界见 [Agent 协议](../integrations/plugins/folio/skills/folio/references/protocol.md)。

## 限制

- 公式和 Mermaid 图表在钉钉中以图片呈现。修改源码后，从 Folio 重新发布；正文和表格可在线编辑。
- 表格与本地图片保留列宽、单元格对齐和图片比例；复杂 HTML、外链资源与特殊排版仍可能存在显示差异。
- “发送链接”不自动更改文档访问权限；同一版本向相同接收人发送会被去重。
- 单张本地图片最大 5 MiB；图片、公式及图表合计上限为 6 MiB（本地图片按文件字节、内嵌数据按编码长度计算），转换后的 JSON 内容上限为 8 MiB。
- 本地 Markdown 始终保留。发布后的阅读与排版请在钉钉中检查。
