# Folio 产品原则

## 文档工作台

人、Claude Code、Codex 及其他工具持续创建和修改文档，资料分布在不同项目，也承载着不同阶段的决定。Folio 提供统一的阅读、查找、管理、编辑和交互入口，并作为人与 Agent 之间的文档桥梁。

## 优先级

1. 文档体验：稳定阅读和编辑，尤其是公式、图、表，以及可靠保存、版本恢复、外部改动处理。
2. 文档组织：自动记住打开过的项目，汇总最近文档，支持跨项目查找，不要求先建立分类体系或维护标签。
3. Agent 入口：独立 CLI、版本条件、来源记录、可分发 skill/plugin，不依赖进入 Codex 或 Claude Code 内部。
4. 可选记忆：MemOS 帮助 Agent 定位应阅读的文档。文档保留为权威原文，记忆只提供必要的导航线索。

## 人与 Agent 的分工

用户正常处理文件。记忆的可见设置只有 API Key 和当前项目的知识库选择／创建。摘要、索引、检索、刷新和旧索引整理由 Agent 处理，不成为人的日常维护任务。

普通界面不提供导航卡编辑、云端检索控制台、发布队列或入库进度管理。没有 MemOS 时，文档应用和本地 Agent 接口仍然工作。

## 多项目与多时间

- 文件夹是已有工作边界；打开项目后自动加入本机文档入口。
- 人可以跨项目查找；Agent 默认限定当前项目，不继承其他项目的知识库。
- 配置 API Key 不会自动为所有项目启用记忆。
- 默认使用当前原文；历史问题显式读取保留的历史版本。
- 文件修改时间、索引时间、任务时间分开记录。旧计划和暂时假设不因被检索到就成为当前事实。
- 任务结束只整理相关、有复用价值的文档，避免收集临时输出、重复草稿和全部聊天。

## 当前边界

文档入口汇总已打开过的文件夹，不扫描整台电脑。不同项目的标签可以同时打开；每份文档保持自己的文件边界，后台标签继续接收外部变化。切换标签只改变当前展示的文件树。启动时是否恢复标签由用户设置；恢复时保留标签顺序和当前文档，草稿单独保存。

查找使用本机可重建的增量索引，工作线程处理文件扫描和查询。结果分页显示，完整 Markdown 仍为权威原文。索引只服务于查找，不负责判断历史内容是否仍有效。

MemOS 检索不保证返回原文件 ID。Folio 用已有版本标识关联原文，关联不明时不按标题猜测。记忆故障不会阻断本地阅读与编辑。
